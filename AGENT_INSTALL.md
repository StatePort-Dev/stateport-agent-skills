# Install or update StatePort agent skills

This is the single installation and update entrypoint for any local coding agent with
MCP tool support. There is no vendor restriction. Determine the current agent
environment and use its supported integration mechanism. It is separate from the
[stateport-debugging workflow](skills/stateport-debugging/SKILL.md): ordinary
debugging must not install a runtime or change user configuration to bypass a
missing capability. Use this entrypoint when the user requests setup or an update.
If StatePort is already installed, use the update procedure below instead of
creating another copy. The current source version is `0.1.0-beta.1`.

## Skills included

Install the complete set through the host's plugin or skill mechanism:

- [stateport-debugging](skills/stateport-debugging/SKILL.md): investigate a Card and verify code changes.
- [stateport-capture](skills/stateport-capture/SKILL.md): record requested state, steps and supplied login, then Review and Save.
- [stateport-journey](skills/stateport-journey/SKILL.md): inspect and replay recorded interactions.
- [stateport-replay-experiments](skills/stateport-replay-experiments/SKILL.md): test request remaps, routing and JSON response changes.
- [stateport-transfer](skills/stateport-transfer/SKILL.md): preview/import .scard or Share URLs, export files and create sharing links.

These skills share public MCP procedures and data-handling rules. Each directory
includes its references and version metadata so a raw install is self-contained.

## Connect before the first Card

1. Install Desktop from the [public download page](https://stateport.dev/download/).
   In Desktop, open **Settings → Coding agents** (**Local MCP** on older Desktop), or follow **Set up coding agent**
   from the empty Library. No Card, Developer trial or agent Capture permission
   is needed to connect. Desktop versions offering **Copy setup** show the
   **Connect an agent** disclosure and generated prompt before copying; older versions offer **Copy MCP config**.
2. Identify your own exact host surface and its existing installation; ask the
   user only if the current environment is ambiguous. Use the matching provider
   guide below, or the generic path for an unlisted agent. Codex CLI is distinct from Codex desktop and
   IDE; a VSIX is distinct from Cursor Agent or Copilot CLI.
3. Preview the smallest change and apply the requested setup using required
   host approvals. Ask the user only for an unresolved conflict or choice beyond
   the request. Use the existing
   native plugin install path and preview-first MCP helper with the configuration
   generated by Desktop. If Desktop explicitly labels supplied configuration as
   a development profile, keep that exact profile and launcher; do not replace it
   with an installed-app configuration. The preview-first helpers below validate
   installed-app configurations only: for this explicit development-profile
   case, use the host's documented native configuration mechanism after preview
   and approval, preserving the supplied command, arguments and environment.
   If that mechanism cannot preserve them, stop and report the limitation.
   Public end-user installation remains
   installer-only. Never invent executable paths, flags, source-checkout launchers
   or install commands. Preserve unrelated MCP entries;
   stop at a conflicting `stateport` entry. Migrate only the confirmed integration-owned
   legacy `scenariodeck` entry explicitly. Do not enable both for one runtime.
   Repeated setup is a no-op or explained repair, not a second plugin/skill copy.
4. Restart the host/session when needed. Verify actual public tool discovery
   from the selected host. Saved configuration, `mcp get`, package installation
   and a direct Desktop probe are separate evidence, not host connection proof.
5. Report the host/version, integration version, last completed step and any
   manual action still needed. **Zero Cards is a valid completed setup.**
   Do not list Cards, inspect unrelated Cards, create synthetic Cards, start
   Capture or enable Capture permission just to test setup. State that the
   connection is verified only after host discovery, and that a case has not
   yet been tested.
6. Continue with the user's task. For a new case, they can capture it in Desktop
   or use **Capture with an agent** in Capture with explicit permission and a
   capable runtime/host. For a saved Card, **Use with agent** previews **Copy task**
   on that exact Card, with optional saved context. First-time connection is
   available inline; no Settings detour or repeated installation is needed.
   Older versions can use the [safe handoff](skills/stateport-debugging/references/handoff.md).

If the registry is offline or a host cannot perform a step, report the blocker
and give the smallest exact manual action from its guide. Do not promise a
universal unattended installer. No private product repository is required.

The five canonical skills above define the same workflows for all agents.
These guides adapt installation and updates to each host:

| Environment | Guide |
| --- | --- |

### An agent without a dedicated adapter

1. Check whether this environment supports local stdio MCP servers and tool
   invocation. Use its documented configuration or installation mechanism;
   do not guess command syntax or configuration paths.
2. Register the `stateport` server using the configuration supplied by Desktop.
   If no configuration was supplied, obtain it with installed `stateport mcp config`
   where available, or ask the user for **Copy MCP config** from Desktop. Do not
   substitute a source checkout or another runtime.
3. Load all five canonical directories under `skills/`, including
   their references and integration metadata, using the agent's supported skill
   mechanism. If it has no skill installer, use its documented project-instruction
   or context mechanism to read the relevant canonical skill and references.
   Do not create a vendor-specific debugging strategy or claim automatic skill
   selection from merely copying files.
4. Apply the same preview, conflict handling and discovery checks above. If the
   environment cannot run the local MCP server, report that precise limitation
   and the smallest supported manual action. Do not pretend it is connected.

Host-specific verification status remains in the [provider registry](providers/registry.json)
and [compatibility inventory](docs/COMPATIBILITY.md). An unlisted agent can use
this generic path; that is not a claim that every host/version has been tested.
Installing or discovering a package is not a completed debugging workflow.
Public Capture availability and permission require separate runtime and host
evidence plus explicit authorization; setup grants none of them.

## Update an existing installation

1. Identify the current host, installation method and installed integration
   version from its plugin details or the skill's `integration.json`. Use the
   requested source/ref; if none is specified, retain the installation's selected
   channel. A pinned tag should not silently move to `main`.
2. Refresh the source and update the existing package with that host's supported
   path below. Check local help if the installed host version differs. Preserve
   unrelated plugins, local customizations and the working MCP configuration.
   The update request authorizes the ordinary update steps; use host approvals
   where required, without asking again for each command.
3. For an alpha installation, ensure all five skills replace the old single-skill
   package. If switching from raw skills to a plugin, remove or disable only the
   confirmed duplicate StatePort copy. Keep a backup of customized copies and
   resolve overlapping changes instead of overwriting them.
4. Restart the session so updated skills load. If Desktop also changed, restart
   the MCP connection and inspect its initialization version and fresh schemas.
   Updating skills alone does not require rewriting a working server entry or
   changing Capture permission.
5. Confirm the installed integration version, all five skill entrypoints and
   actual host MCP discovery. Report precisely what was checked and any remaining
   manual step. This check needs no Card reads or new Capture. Resume the task.

### Host update commands

**Codex CLI** (the CLI help exposes marketplace upgrade and plugin remove/add):

```sh
codex plugin marketplace upgrade stateport-dev
codex plugin remove stateport@stateport-dev
codex plugin add stateport@stateport-dev
```

Check that refresh succeeded before removing the installed package. Retain its
old version/ref for recovery if reinstall fails. Do not remove the MCP server.
For Codex desktop/IDE, use the actual surface's supported update controls or
its raw-skill path rather than assuming the CLI updates that installation.

**Claude Code**:

```sh
claude plugin marketplace update stateport-dev
claude plugin update stateport@stateport-dev
```

Preserve the existing install scope; use the host's scope option if necessary.
See [Claude's update documentation](https://code.claude.com/docs/en/discover-plugins).

**GitHub Copilot CLI**:

```sh
copilot plugin marketplace update stateport-dev
copilot plugin update stateport
```

See the [Copilot plugin reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference).

**Cursor Agent / raw skills / another local host**: update the reviewed selected
checkout or replace the installed StatePort directories from the chosen source.
For a clean clone tracking the requested branch, use `git pull --ff-only`.
If it has local changes or is pinned to a tag, preserve them and resolve the
requested target first. Copy all five complete skill directories, not just
SKILL.md; plugin installs need the whole `plugins/stateport` directory. Restart
the host and check discovery.

**VS Code/Cursor VSIX and JetBrains ZIP**: install the newer reviewed artifact
through the editor's extension/plugin UI and reload as requested. Follow the
matching provider guide above; source version changes do not create a built
artifact or prove host support.

An update fails safely if the requested source is unavailable: retain or restore
the previous reviewed integration, keep MCP configuration, and report the exact
failed step. Do not report the new version loaded solely because its catalog
was refreshed. [Versioning and updates](docs/VERSIONING_AND_UPDATES.md) records
source/release distinctions and host-specific verification status.
