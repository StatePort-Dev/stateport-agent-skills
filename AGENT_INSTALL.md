# Connect your coding agent to StatePort

This is the single install/setup entrypoint for any local coding agent with
MCP tool support. There is no vendor restriction. Determine the current agent
environment and use its supported integration mechanism. It is separate from the
[stateport-debugging workflow](skills/stateport-debugging/SKILL.md): ordinary
debugging must not install a runtime or change user configuration to bypass a
missing capability. Use this entrypoint only when the user requests setup.

## Connect before the first Card

1. Install Desktop from the [public download page](https://stateport.dev/download/).
   In Desktop, open **Settings → Coding agents** (**Local MCP** on older Desktop), or follow **Set up coding agent**
   from the empty Library. No Card, Developer trial or agent Capture permission
   is needed to connect. Desktop versions offering **Copy setup** show the
   generated prompt before copying; older versions offer **Copy MCP config**.
2. Identify your own exact host surface and its existing installation; ask the
   user only if the current environment is ambiguous. Use the matching provider
   guide below, or the generic path for an unlisted agent. Codex CLI is distinct from Codex desktop and
   IDE; a VSIX is distinct from Cursor Agent or Copilot CLI.
3. Preview the smallest change and obtain host/user approvals. Use the existing
   native plugin install path and preview-first MCP helper with the configuration
   generated by the installed Desktop. Never invent executable paths, flags,
   source-checkout launchers or install commands. Preserve unrelated MCP entries;
   stop at a conflicting `stateport` entry. Migrate only the confirmed integration-owned
   legacy `scenariodeck` entry explicitly. Do not enable both for one runtime.
   Repeated setup is a no-op or explained repair, not a second plugin/skill copy.
4. Restart the host/session when needed. Verify actual public tool discovery
   from the selected host. Saved configuration, `mcp get`, package installation
   and a direct Desktop probe are separate evidence, not host connection proof.
5. Report the host/version, integration version, last completed step and any
   manual action still needed. **Zero Cards is a valid completed setup.**
   Do not list Cards, inspect unrelated Cards, create synthetic Cards, start
   Capture or enable Capture permission just to test setup. State that the
   connection is verified only after host discovery, and that a case has not
   yet been tested.
6. Ask the user to record their first case with Desktop **Capture → Review → Save**.
   The Card's secondary setup/instructions link returns to Settings with exact
   identity for **Copy task**. No repeated installation is needed. Older Desktop
   versions can use the [safe handoff](skills/stateport-debugging/references/handoff.md).

If the registry is offline or a host cannot perform a step, report the blocker
and give the smallest exact manual action from its guide. Do not promise a
universal unattended installer. No private product repository is required.

## Choose the integration for this environment

The shared [stateport-debugging skill](skills/stateport-debugging/SKILL.md) owns
one debugging workflow for all agents. These guides adapt installation only:

| Environment | Guide |
| --- | --- |
| Codex CLI, desktop or IDE | [Codex](providers/codex/README.md) — distinguish the exact surface |
| Claude Code | [Claude](providers/claude/README.md) |

| Another local coding agent | Generic path below |

### An agent without a dedicated adapter

1. Check whether this environment supports local stdio MCP servers and tool
   invocation. Use its documented configuration or installation mechanism;
   do not guess command syntax or configuration paths.
2. Register the `stateport` server using the configuration supplied by Desktop.
   If no configuration was supplied, obtain it with installed `stateport mcp config`
   where available, or ask the user for **Copy MCP config** from Desktop. Do not
   substitute a source checkout or another runtime.
3. Load the entire canonical `skills/stateport-debugging` directory, including
   its references and integration metadata, using the agent's supported skill
   mechanism. If it has no skill installer, use its documented project-instruction
   or context mechanism to read the canonical skill and referenced workflow.
   Do not create a vendor-specific debugging strategy or claim automatic skill
   selection from merely copying files.
4. Apply the same preview, conflict handling and discovery checks above. If the
   environment cannot run the local MCP server, report that precise limitation
   and the smallest supported manual action. Do not pretend it is connected.

Host-specific verification status remains in the [provider registry](providers/registry.json)
and [compatibility inventory](docs/COMPATIBILITY.md). An unlisted agent can use
this generic path; that is not a claim that every host/version has been tested.
Installing or discovering a package is not a completed debugging workflow.
Public Capture availability and permission require separate runtime and host
evidence plus explicit authorization; setup grants none of them.
